# CS330-Bookshelf-Project
OpenGL C++ graphics project

During the process of designing this scene, I was able to learn how to take a reference and break it down into objects, figuring out what to simplify, keep, and extend. I based my scene on a real shelf from my bookshelf, so I looked at each object (candle, notebook, BTS lightstick, Chococat plush, Canon camera) and broke it into basic shapes that could approximate their outline. From there I decided which materials and textures would make each one look right, such as black plastic and fur textures, and then designed the lighting around the lightstick's blue glow. The designing process I followed was to pick a reference (object by object), decompose it into simple shapes, assign materials/textures, and then of course, make sure the lighting in the scene was the way I wanted it to be.


I developed the scene in small steps, adding one object at a time and checking how it looked before moving on. Iteration mattered most with lighting. My white lights kept overpowering the blue light meant to mimic the lightstick, so I had to repeatedly tone down the white lights' ambient and diffuse values until the blue could show, then adjust again so nothing was blown out. My code organization evolved the same way. I originally defined every object in PrepareScene(), but it got too long to manage, so I moved each object into its own function. Over the course of the milestones, I focused on a different aspect of graphics, so I learned gradually and built on what I already had instead of jumping from topic to topic.


My goal is to become a full stack software engineer, and this project helped me to hone skills that apply directly. Working with OpenGL meant learning an API I didn't write, reading its documentation, and wrapping its calls in my own functions so my code stayed readable. Full stack work involves the similar work every day, whether it's a REST API, or a database library. When it comes to my education, learning graphics helped to strengthen my C++ and OOP skills. It also allowed me to practice working in an established    code base which will carry over to both team projects and real world work. The debugging habits of incrementally changing and running the program will stick with me in my future projects as well.
